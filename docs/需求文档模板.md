# 需求文档模板

> 此模板用于编写需求文档，Cursor AI将根据此格式自动生成测试用例

---

## 模板1: API接口需求文档

### 功能名称
[接口功能的简短描述，如：用户登录]

### 功能描述
[详细的功能说明，包括业务背景和目标]

示例：
用户通过用户名和密码登录系统，登录成功后获取访问token，用于后续API调用的身份验证。

### 接口定义

#### 基本信息
- **接口路径**: `/api/xxx`
- **请求方法**: `POST` / `GET` / `PUT` / `DELETE`
- **Content-Type**: `application/json`
- **是否需要认证**: 是/否

#### 请求参数

| 参数名 | 类型 | 必填 | 约束 | 说明 | 示例 |
|--------|------|------|------|------|------|
| username | string | 是 | 长度3-20 | 用户名 | "testuser" |
| password | string | 是 | 长度6-20 | 密码 | "password123" |
| remember | boolean | 否 | true/false | 记住登录 | false |

#### 响应格式

**成功响应** (200):
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "userId": 123,
    "username": "testuser",
    "expiresIn": 86400
  }
}
```

**失败响应** (400):
```json
{
  "code": 400,
  "message": "错误描述",
  "data": null
}
```

### 业务规则

1. **认证规则**
   - 用户名和密码必须完全匹配
   - 密码区分大小写

2. **安全规则**
   - 密码错误3次后锁定账户30分钟
   - token有效期24小时
   - 同一账户同时只能有一个有效token

3. **数据规则**
   - 用户名不能包含特殊字符
   - 密码必须包含字母和数字

### 异常处理

| 场景 | HTTP状态码 | 返回消息 | 说明 |
|------|-----------|---------|------|
| 用户名不存在 | 400 | "用户不存在" | 用户名在系统中未注册 |
| 密码错误 | 400 | "密码错误" | 密码不匹配 |
| 账户被锁定 | 403 | "账户已锁定，请30分钟后重试" | 密码错误超过3次 |
| 缺少必填参数 | 400 | "缺少必填参数: xxx" | 请求参数不完整 |
| 参数格式错误 | 400 | "参数格式错误: xxx" | 参数类型或格式不正确 |

### 依赖接口

- 无（独立接口）

### 注意事项

- token需要保存在客户端，后续请求需在Header中携带：`Authorization: Bearer {token}`
- token过期后需要重新登录
- 生产环境需要HTTPS加密传输

## 模板2: 简化版需求文档

```markdown
# 用户查询接口

## 接口
- 路径: /api/users
- 方法: GET
- 参数: page(页码,必填), size(每页数量,必填), keyword(关键词,可选)
- 认证: 需要token

## 成功响应
{
  "code": 200,
  "data": {
    "totalCount": 100,
    "list": [...]
  }
}

## 异常
- page<1: "页码不能小于1"
- size>100: "每页数量不能超过100"
- 无权限: "无权访问"
```

## 模板4: OpenAPI/Swagger规范

```yaml
openapi: 3.0.0
info:
  title: 用户管理API
  version: 1.0.0

paths:
  /api/login:
    post:
      summary: 用户登录
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required:
                - username
                - password
              properties:
                username:
                  type: string
                  minLength: 3
                  maxLength: 20
                  description: 用户名
                password:
                  type: string
                  minLength: 6
                  maxLength: 20
                  description: 密码
      responses:
        '200':
          description: 登录成功
          content:
            application/json:
              schema:
                type: object
                properties:
                  code:
                    type: integer
                    example: 200
                  token:
                    type: string
                  userId:
                    type: integer
        '400':
          description: 登录失败
```

## 使用方法

### 方法1: 在Cursor中直接生成

1. 将需求文档保存到 `AI_TEST/docs/` 目录
2. 在Cursor中按 `Cmd+I`
3. 输入:
```
@docs/你的需求文档.md
根据这个需求文档生成完整的测试用例
保存到 cases/api/模块名/
```

### 方法2: 批量生成

如果有多个需求文档：
```
@docs/需求文档/
批量生成该目录下所有需求文档的测试用例
保存到 cases/api/ 对应子目录
```

### 方法3: 增量生成

需求文档更新时：
```
@docs/用户登录需求.md
这个需求文档已更新
对比已有测试 @cases/api/user_login.yaml
只生成新增或修改的场景
```

## 最佳实践

### 1. 需求文档编写建议

✅ **推荐做法**:
- 接口定义清晰明确
- 参数约束详细（类型、长度、范围）
- 异常场景完整
- 业务规则明确

❌ **避免**:
- 模糊的描述（"大概"、"可能"）
- 缺少参数约束
- 遗漏异常场景
- 业务规则不清晰

### 2. 参数约束示例

```markdown
| 参数名 | 类型 | 必填 | 约束 | 说明 |
|--------|------|------|------|------|
| age | integer | 是 | 1-150 | 年龄 |
| email | string | 是 | 邮箱格式 | 邮箱地址 |
| status | string | 否 | 枚举:active/inactive | 状态 |
| score | float | 是 | 0-100,保留2位小数 | 分数 |
```

Cursor AI会根据这些约束自动生成边界值测试！

### 3. 异常场景示例

```markdown
## 异常处理

### 参数校验异常
- 缺少username: "用户名不能为空"
- username长度<3: "用户名长度必须在3-20之间"
- password格式错误: "密码必须包含字母和数字"

### 业务逻辑异常
- 用户名不存在: "用户不存在"
- 密码错误: "密码错误，还可尝试N次"
- 账户锁定: "账户已锁定，请30分钟后重试"

### 权限异常
- 未登录: "请先登录"
- token过期: "登录已过期，请重新登录"
- 无权限: "无权访问该接口"
```

Cursor AI会为每个异常场景生成对应测试！

## 常见问题

### Q1: 需求文档格式不标准怎么办？

**A**: Cursor AI支持灵活解析，只要包含关键信息（接口路径、参数、响应）即可。不过标准格式生成效果更好。

### Q2: 如何生成更全面的测试？

**A**: 在需求文档中详细描述：
- 参数的所有约束
- 所有可能的异常场景
- 详细的业务规则

### Q3: 可以直接用产品经理的PRD文档吗？

**A**: 可以！Cursor AI会自动提取关键信息。建议在提示词中明确说明：
```
@prd/产品需求文档.md
这是产品需求文档
提取接口相关信息
生成测试用例
```

**提示**: 需求文档越详细，生成的测试用例越完善！
