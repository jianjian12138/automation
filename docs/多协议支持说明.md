# AI_TEST 多协议支持说明

## 📋 概述

AI_TEST框架现在支持多种通信协议，不仅限于HTTP，还支持：
- **HTTP/HTTPS** - 标准HTTP协议（默认）
- **WebService (SOAP)** - SOAP协议的WebService调用
- **WebSocket** - WebSocket实时通信
- **Dubbo** - Apache Dubbo RPC调用
- **MQTT** - MQTT消息发布订阅

---

## 🏗️ 架构设计

### 协议适配器模式

框架采用**协议适配器模式**，所有协议适配器继承自`ProtocolAdapter`基类，提供统一的接口：

```python
class ProtocolAdapter(ABC):
    @abstractmethod
    def send_request(self, step: Dict) -> Dict:
        """发送请求"""
        pass
    
    @abstractmethod
    def validate_response(self, response: Dict, assert_config: Dict) -> list:
        """验证响应"""
        pass
```

### 支持的协议

| 协议 | 适配器类 | 协议别名 | 说明 |
|------|---------|---------|------|
| HTTP | `HTTPAdapter` | `http`, `https` | 标准HTTP/HTTPS协议 |
| WebService | `WebServiceAdapter` | `webservice`, `soap` | SOAP协议WebService |
| WebSocket | `WebSocketAdapter` | `websocket`, `ws`, `wss` | WebSocket实时通信 |
| Dubbo | `DubboAdapter` | `dubbo` | Apache Dubbo RPC |
| MQTT | `MQTTAdapter` | `mqtt` | MQTT消息协议 |

## 📝 使用方法

### 1. HTTP协议（默认）

HTTP协议是默认协议，无需指定`protocol`字段：

```yaml
steps:
  - step_name: HTTP GET请求
    host: https://api.example.com
    path: /users/1
    method: GET
    headers:
      Authorization: Bearer token123
    response_assert:
      status_code_assert: 200
```

### 2. WebService (SOAP)协议

```yaml
steps:
  - step_name: SOAP服务调用
    protocol: webservice  # 或 soap
    wsdl_url: http://www.example.com/service.asmx
    operation: GetUserInfo
    params:
      userId: "123"
      userName: "test"
    response_assert:
      status_code_assert: 200
      xpath_assert:
        "//GetUserInfoResult/UserId": "123"
```

**或者使用自定义SOAP Body：**

```yaml
steps:
  - step_name: 自定义SOAP请求
    protocol: soap
    host: http://www.example.com/service.asmx
    soap_body: |
      <GetUserInfo xmlns="http://tempuri.org/">
        <userId>123</userId>
      </GetUserInfo>
    response_assert:
      status_code_assert: 200
```

### 3. WebSocket协议

```yaml
steps:
  - step_name: WebSocket连接和消息
    protocol: websocket  # 或 ws, wss
    ws_url: wss://echo.websocket.org
    message:
      type: test
      data: Hello WebSocket
    wait_response: true      # 是否等待响应
    wait_timeout: 5          # 等待超时时间（秒）
    close_after: true        # 发送后是否关闭连接
    connection_id: conn1     # 连接ID（用于复用连接）
    response_assert:
      status_code_assert: 200
      message_assert: Hello WebSocket
```

**WebSocket连接复用：**

```yaml
steps:
  # 第一次连接，保持连接
  - step_name: 建立连接
    protocol: websocket
    ws_url: ws://localhost:8080/ws
    connection_id: my_conn
    message: "ping"
    wait_response: true
    close_after: false  # 不关闭，保持连接
    
  # 复用同一个连接
  - step_name: 发送消息
    protocol: websocket
    ws_url: ws://localhost:8080/ws
    connection_id: my_conn  # 使用同一个连接ID
    message: "get_data"
    wait_response: true
```

### 4. Dubbo协议

```yaml
steps:
  - step_name: Dubbo服务调用
    protocol: dubbo
    host: 192.168.1.100
    port: 20880
    interface: com.example.service.UserService
    method: getUserById
    parameters:
      - "123"
    version: 1.0.0
    group: user
    response_assert:
      status_code_assert: 200
      jsonpath_assert:
        - $.id == "123"
        - $.name != null
```

### 5. MQTT协议

**发布消息：**

```yaml
steps:
  - step_name: 发布MQTT消息
    protocol: mqtt
    action: publish
    broker: mqtt.example.com
    port: 1883
    topic: sensors/temperature
    message:
      sensor: temp1
      value: 25.5
      timestamp: "2025-10-31T10:00:00Z"
    qos: 1
    client_id: publisher1
    username: test_user    # 可选
    password: test_pass    # 可选
    response_assert:
      status_code_assert: 200
```

**订阅主题：**

```yaml
steps:
  - step_name: 订阅MQTT主题
    protocol: mqtt
    action: subscribe
    broker: mqtt.example.com
    port: 1883
    topic: sensors/temperature
    qos: 1
    client_id: subscriber1
    wait_messages: 5      # 等待接收5条消息
    wait_timeout: 30     # 等待超时30秒
    response_assert:
      status_code_assert: 200
      message_assert: temperature
      jsonpath_assert:
        - $.value >= 20
```

## 🔧 配置说明

### 协议特定配置

可以在`config/environment.yaml`中为每个协议配置特定参数：

```yaml
http:
  timeout: 30

webservice:
  timeout: 30

websocket:
  timeout: 30
  connection_timeout: 10

dubbo:
  timeout: 30

mqtt:
  timeout: 30
```

## ✅ 断言支持

### HTTP协议断言

- `status_code_assert`: 状态码断言
- `response_assert_data`: 响应消息断言
- `jsonpath_assert`: JSONPath断言

### WebService断言

- `status_code_assert`: 状态码断言
- `xpath_assert`: XPath断言（用于XML响应）
- `response_assert_data`: 响应消息断言

### WebSocket断言

- `status_code_assert`: 连接状态码（200表示成功）
- `message_assert`: 消息内容断言
- `jsonpath_assert`: JSONPath断言（如果消息是JSON格式）

### Dubbo断言

- `status_code_assert`: 状态码断言
- `jsonpath_assert`: JSONPath断言
- `response_assert_data`: 响应消息断言

### MQTT断言

- `status_code_assert`: 状态码断言
- `message_assert`: 消息内容断言
- `jsonpath_assert`: JSONPath断言（如果消息是JSON格式）
- `response_assert_data`: 响应消息断言

## 🔄 协议自动推断

如果不指定`protocol`字段，框架会尝试自动推断协议：

1. **WebSocket**: URL以`ws://`或`wss://`开头
2. **Dubbo**: 主机包含`dubbo`或端口为`20880`
3. **MQTT**: 包含`topic`字段或`action`为`publish`/`subscribe`
4. **HTTP**: 其他情况默认使用HTTP

## ⚙️ 依赖安装

安装所有协议支持的依赖：

```bash
pip install -r requirements.txt
```

主要依赖：
- `websockets==12.0` - WebSocket支持
- `paho-mqtt==1.6.1` - MQTT支持
- `requests` - HTTP/WebService支持（已包含）

---

## 📝 注意事项

1. **WebSocket**: 需要异步库支持，某些场景可能需要额外配置
2. **Dubbo**: Dubbo协议实现是简化版本，复杂场景可能需要扩展
3. **MQTT**: 订阅操作需要等待Broker发送消息，确保Broker正常运行
4. **WebService**: 需要服务器支持SOAP协议，并提供正确的WSDL

---

## 🔍 调试建议

1. **查看日志**: 每个协议适配器都会输出详细的日志，包括请求和响应信息
2. **检查响应**: 响应结果保存在`result['response']`中，可以查看详细信息
3. **协议推断**: 如果协议自动推断失败，显式指定`protocol`字段
4. **连接复用**: WebSocket和MQTT支持连接复用，注意`connection_id`的使用
